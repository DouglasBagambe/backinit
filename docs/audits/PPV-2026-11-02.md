# PPV feature audit — 2 November 2026

Reference: owner screenshots plus direct browser inspection of https://ppv.st/ , https://ppv.st/multiview and https://ppv.st/api . This is a functional reference, not a visual design to copy.

## Confirmed behavior

- Searchable stream directory grouped by sport; jump links; live/channel labels, kickoff countdowns, posters and viewer badges.
- Multiview offers 2, 3 or 4 slots. Equal tiles or one main screen with smaller tiles; each empty slot opens a searchable, sport-grouped stream chooser. Layout state is reflected in the URL (`n`, `main`).
- Owner's player screenshots show source switching, viewer count, sharing, theatre/pop-out/fullscreen controls and a chat panel with an entry notice/settings/connection status.
- Header exposes stream requests, VOD archive and account links. VIP is visibly closed, so it is not a working paid-feature reference.
- Public API docs describe category/stream objects with stable IDs, titles, posters, timestamps, uri_name and optional iframe. Browser/source metadata does not establish reliable current playback or redistribution rights for every event.

## Supported integration route

The published API page explicitly allows other-site use (`Access-Control-Allow-Origin: *`) and backend use with sensible caching, recommends approximately one-minute polling, and says supplied iframe strings can render directly when present. It forbids altering embeds, sandboxing required functionality, or bypassing ad/integration rules. Example READ_ME says to contact them for more information; no message was sent. Use documented response fields and supplied embeds; do not extract hidden media URLs or remove embedded ads. Missing iframe means no assumed playable feed.

Public endpoints documented: `https://api.ppv.st/api/streams` and `/api/ping`. If implemented, cache centrally at least 60 seconds, bound upstream latency, validate fields/iframe origins, preserve last known catalogue with explicit freshness, and keep failures independent of the existing catalogue. Never invent viewer counts or call directory availability proof of a working stream.

## BackInIt implementation specification after the ad release

Preserve Green 2, existing typography and mobile navigation. Add a dedicated Multiview route with 2/3/4 slots, equal/focus layouts, keyboard-accessible stream chooser, swap/remove/promote controls, one audible player at a time where the player API supports it, and a shareable URL. On narrow screens use a readable vertical arrangement rather than four tiny players.

Match view should retain one dominant player, compact real-data tracker beside/below it, clear source selection and recovery state, theatre/fullscreen/PiP where supported, and honest stream health. Optional chat needs real backend persistence/presence, moderation, rate limiting, reporting and privacy treatment. Viewer totals must measure actual BackInIt activity; PPV's totals must never be relabelled as our own. Stream requests should have a submission/review workflow, not publish arbitrary user embeds.

Acceptance: desktop/mobile layouts; independent tile failures; removal stops playback; refresh restores selection; no overlapping audio; slow/missing streams do not freeze navigation; source changes recover; ad formats do not cover controls; counters and chat remain correct across reconnects. Test supplied embeds end-to-end without bypassing their ad behavior.
